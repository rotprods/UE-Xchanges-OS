# Checkpoint — 2026-08-28 — v0.6 Outcome Learning

## Trigger

The private CRM now contains enough heterogeneous outcomes to prove that a single binary accepted/rejected label is unsafe:

- an accepted/completed historical Ticket2Europe mobility;
- a current first-place waitlist with BreGal;
- a historical rejection from a 430+ applicant pool with no individual feedback.

Treating all three as equal training examples would corrupt selection heuristics.

## Design decision

Do **not** build an acceptance-probability model yet. Three outcomes do not support calibrated forecasting.

Instead, encode which learning updates are allowed from each outcome class and which causal inferences are forbidden.

## Implementation

`src/uexchanges/outcomes.py`

Canonical outcome classes:
- `ACCEPTED_COMPLETED`
- `ACCEPTED`
- `WAITLIST_PRIORITY`
- `REJECTED_WITH_FEEDBACK`
- `REJECTED_HIGH_COMPETITION`
- `REJECTED_NO_REASON`
- `NO_RESPONSE`
- `WITHDRAWN`

Each record maps to a `LearningPolicy` containing:
- selection signal;
- causal strength;
- permitted prior/heuristic updates;
- near-accept flag;
- forbidden inferences;
- explanation.

## Hard rules

1. Priority waitlist ≠ ordinary rejection.
2. Waitlist rank 1–3 may create a weak positive/near-accept prior; never a negative application penalty without feedback.
3. High-competition rejection without individual reason updates competition/base rate only.
4. No-response updates organisation response behaviour only; it is not a verified rejection.
5. Acceptance/completion supports a positive selection/relationship prior but does not prove every application component caused acceptance.
6. Only explicit organiser feedback can update call-specific negative criterion heuristics.
7. Specific feedback remains call/criterion scoped and never becomes a universal rule.
8. Historical application claims remain self-reported unless independently verified.

## Tests added

Regression coverage includes:
- accepted/completed positive prior without component causality;
- rank-1 waitlist as near-accept, not negative;
- 430+ high-competition rejection as base-rate-only evidence;
- explicit feedback enabling only specific heuristic learning;
- feedback outcome requiring actual feedback;
- no-response not being a rejection;
- waitlist requiring rank;
- invalid waitlist rank rejected.
