# Checkpoint — 2026-08-28 — v0.7 Execution Orchestrator

## Trigger

The first real execution wave proved that the system could discover, verify, score and prepare dossiers, but operational state still depended on agents manually choosing a next step across Gmail, Drive, Todoist and authenticated external portals.

Two production incidents made the missing layer explicit:

1. a deadline correction for Triglav required urgent cross-system remediation;
2. after the deadline, no connected submission receipt existed, but that absence could not truthfully be converted into `NOT_SUBMITTED`.

The system needed a deterministic execution router and a canonical campaign contract.

- `tests/test_execution.py` — deadline, receipt, eligibility, private-gate, form, AI-policy, review and submission regressions;

- Drive Execution Command Center v0.7.

## Router precedence

```text
submission/receipt/outcome integrity
 -> crossed deadline
 -> source
 -> fact conflict
 -> deadline
 -> external clarification
 -> public eligibility
 -> private gates
 -> form capture
 -> AI policy
 -> human writing/review
 -> submission
```

## New invariants

- crossed deadline + no visible receipt = `VERIFY_RECEIPT`, not assumed non-submission;
- only explicit non-submission may produce `CLOSED_NOT_SUBMITTED`;
- submitted state without a stored receipt remains incomplete;
- source/fact/external/public/private/policy gates outrank Fit Score;
- `AI_UNKNOWN` blocks final-answer generation;
- `AI_FINAL_TEXT_PROHIBITED` routes to human writing;
- timezone-naive deadline input is rejected;
- each completed reply ingestion emits exactly one mandatory next operation.
